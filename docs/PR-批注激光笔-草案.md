# PR 草案：修 QQ 屏幕共享的批注 / 激光笔（叠加窗口尺寸未按输出缩放换算）

> **⚠️ 发现环境：niri** —— 本文所有实测都在 niri 上做的，**KDE / GNOME 未验证** ✗。

## 环境与发现场景

| 项 | 值 |
|---|---|
| 合成器 | **niri**（自编译，含 `niri-portal-cast` 补丁，采集**只宣告 SHM**）|
| 输出 | 2560×1600 @ **scale 1.5** → 逻辑 **1706×1066**；分数缩放走 `wp_fractional_scale_v1` |
| 共享路径 / 客户端 | `xdg-desktop-portal` + PipeWire；QQ 3.2.34-53644 + `linuxqq-wayland-fix` 0.2.14.test3-1 |

**本文所有数字都来自上表这台机器** ✓；"KDE / GNOME 的 150% 缩放是否同样表现"**未验证** ✗，
请勿据此推断"所有合成器都一样" ✗。

## 结论

批注 / 激光笔靠一块**独立的"绘制窗口"**实现：建为叠加层后由 AVSDK（`libAVSDKPlugin.so`）经
`StartDrawingWindowCapture` 单独捕获并合成进共享流。**niri（scale 1.5）** 实测：该窗口自报的
逻辑尺寸**恒等于物理分辨率（2560×1600）、不随缩放变化** ✗ → 比逻辑屏幕大 1/scale 倍，坐标原点错位。
（"是否对分数缩放一概不处理"**待验证** —— 只有 niri 的证据 ✓。）

## 根因证据（niri 实测：输出 2560×1600，逻辑尺寸随 scale 变化）

| 输出 scale | 逻辑屏幕 | 叠加窗口自报（`niri msg windows`）| 结果 |
|---|---|---|---|
| 1 | 2560×1600 | 2560×1600 | **正确** ✓（"scale 1 更正常"）|
| **1.5** | **1706×1066** | **2560×1600** | 大 **1.5** 倍 ✗ |
| 2 | 1280×800 | 2560×1600 | 大 **2** 倍 ✗ |

症状链：画布比屏幕大 → 坐标原点错 → 工具条出现在"逻辑中心"、笔迹落点偏移 → 设成全屏时整块不透明表面铺满 → **所有窗口变黑** ✗

## 复现（niri）

```bash
niri msg output eDP-1 scale 1.5      # 确保是分数缩放；开共享 → 开批注 / 激光笔
niri msg windows | grep -B2 -A6 '屏幕共享'   # 看那块浮动窗口自报的尺寸
```
判据：自报 **2560×1600** 而逻辑屏只有 **1706×1066** → 复现 ✓；把 scale 改成 `1`/`2` 再看，
自报尺寸**始终 2560×1600**（完全不随缩放变化）✓

## 实现落点（本次新取证）

- `libAVSDKPlugin.so` 里这条链（`strings` 可见）：`...StartDrawingWindowCaptureEjm` / `...RemoveDrawingWindowCaptureEj` /
  `...LogDrawingRectEPKcjPS1_S2_Pmjj`，日志串 `avsdk output(wrapper): StartDrawingWindowCapture Screen Capture`
  → **捕获 + 合成在 AVSDK 里** ✓，与 PR #28 挂钩 `CreateH264Encoder` **同属一个库**，项目既有手法可复用 ✓
- **QQ 主进程是原生 Wayland 客户端** ✓（0 个 X11 socket、4 个 Wayland socket）→ X11 几何 hook 不通 ✗
- **`libqq-borderfix.so` 与这块窗口无关** ✗（源码无 X11 / `wl_surface` / GTK / 尺寸调用）

## 已试过且无效的路（避免作者重复走）

| 做法 | 结果 | 原因 |
|---|---|---|
| `--force-device-scale-factor=1` 启动 QQ | ✗ | 不影响这块窗口的逻辑尺寸 |
| niri `set-window-width/height`、`window-rule` | ✗ 客户端仍按错基准画 | 改的是合成器侧，改不了客户端自报尺寸 |
| 把该窗口全屏 | ✗ 整块不透明铺满 → **所有窗口变黑** | 表面本身就是 1.5 倍大且不透明 |

## 修法候选（均需 scale=1 幂等）

- **A（推荐先试）**：挂钩 `StartDrawingWindowCapture`（必要时含另两个），把绘制窗口的**捕获几何**按当前输出 scale 换算 ✓
- **B**：在窗口创建处修正逻辑尺寸 —— 先定位**谁创建**它（Electron/JS 还是 native lib，见"待确认"）

## 必须满足的约束

- **scale = 1 时幂等**（除以 1 = 不变 ✓）—— 审查会盯这点
- 不改变其它 QQ 窗口、不影响共享本身
- 不破坏 X11 / KDE / GNOME（各环境缩放机制不同；**KDE / GNOME 未验证** ✗）
- 失败必须回落（画不出 ≠ 崩），与项目既有安全网一致
